# 考试锻造器（exam-forge）

**这个工具要造的不是「练习题」，是「可预期性」。** 用户考前的核心痛苦不是「不会」，是「不知道会考什么」。所以它的成功标准不是押中题，而是**开考那一刻不慌**。

## 三根轴（全部模式共用）

1. **知识界限 = 用户喂进来的资料里出现的知识点的并集。** 不是章节边界，是知识点集合。所以：**没喂进来的，不许考**；喂进来的，不许漏记。
2. **知识点不变，题型尽量保留。** 变的是皮（措辞、情境、选项），不变的是知识点。用户明确说不要某题型才砍——**那是他给自己划的停止线，不要劝他加回来**。
3. **出卷与刷题可以完全解耦。** 刷题可以直接消费出卷的产物，也可以消费用户从别处拿来的卷子或题库。

## ⚠️ 前置条件：这个技能需要可写目录

**先看这一节，再看别的。**

本技能的记忆**全部落在文件上**：

| 文件 | 用途 | 写不了的后果 |
|---|---|---|
| `output/科目/错题本.md` | **跨会话、跨模型记忆的载体** | 错题本没了 → 下次出卷没有加权依据（`mode-出卷.md` 第 8 步）→ 换皮重做失去原料（`mode-刷题.md`） |
| `output/科目/待确认清单.md` | 存用户对答案的质疑 | 质疑丢了 → 用户退回到"全都不可信" |
| `specs/科目名.md` | 科目规则沉淀 | 「不用每次重新教 AI」永远不生效 |

**先确认工作目录可写**，再做别的。

**默认假设是可写**——大多数 agent 环境、IDE、带项目目录的客户端都能写。直接动手即可。

**只有真的写盘失败时**，才进入降级路径：

1. **当场如实告诉用户：「这个目录写不了，错题本 / 待确认清单 / 规格存不下来。」** 附上具体路径。
2. **说清楚丢的后果**：跨会话记忆没了、下次出卷没有加权依据、质疑存不住。
3. **继续提供服务，但把该落盘的东西变成对话里落盘**：把内容以完整文本输出，**明确请用户自己复制保存**，并告诉他下次把文件发回来就能恢复。
4. **绝不假装存了。** 不许说「已记入待确认清单」「已写入错题本」。**不产生文件却宣布写入成功，是这个技能最严重的一类失败。**

**不同文件的致命程度不一样**：错题本 / 待确认清单**是关键**（跨会话记忆全靠它）；`specs/` 是**可降级**的（本轮行为不受影响，只是下次要重讲）。所以写不了 specs 时可以照常出卷，**但依然要如实说一句「规格没存上」**。

> 在一个只读环境里，本技能**仍然可以出卷和刷题**——只是会退化成一节性的、没有记忆的用法。**这没问题，前提是用户知道。**

**顺带一条常见用法**：用户可能**在这里出好卷子，拿试卷和解析去找免费模型刷题**，刷完把错题列表带回来。这条路走得通正是因为记忆是文件。遇到这种情况**照收错题列表并归档**，他是带回来复核和归整的，**不是来听"我建议你在这里刷"的**。

## 模式契约（先读这一节再动手）

| 模式 | 何时进入 | 读哪个文件 | 绝对不要做 |
|---|---|---|---|
| **出卷** | 用户要卷子、丢资料、说「出题」「生成模拟卷」 | `references/mode-出卷.md` | 不要在出卷时进入逐题问答，也不要替用户做题 |
| **刷题** | 用户说开始刷题、做题、辅导我、给了范围要练 | `references/mode-刷题.md` + `references/rules-verbatim.md` | **不要在刷题时输出知识点总结、学习建议、进度报告、鼓励语** |
| **知识点直出** | 用户直接丢知识点 / 关键词列表，不要整份卷子 | `references/mode-直出.md` | 不要强行要求用户先提供资料或卷型大纲 |
| **建科 / 改规格** | **只有用户明确说「帮我建一门新课的规格」** | `references/specs-管理与建科.md` | **不要主动建议建科、不要主动追加规格** |

**按需读取，不要一次读完整个技能。** 用户说"刷题"就只读刷题那两份，别把出卷那份也灌进上下文。

**刷题模式的约束最高优先级。** 用户是临考的人，你的任何多余输出都是噪音。

**规格相关的一切都是被动的**：用户不提，就不提。详见 `references/specs-管理与建科.md`。

## 编号命名空间

题目来自五个来源，**落盘、排序、历史回溯一律用完整编号，不许用裸题号**：

| 来源 | 格式 | 例 |
|---|---|---|
| 出卷模式的基础题 | `卷次-序号` | `A卷-1`、`A卷-12` |
| 出卷模式的加权追加题 | `卷次-W序号` | `A卷-W1` |
| 刷题模式的换皮题 | `卷次-变序号` | `A卷-变1` |
| 知识点直出模式的题 | `直出-YYYYMMDD-NN` | `直出-20260919-03` |
| 外部拿来的卷子 | `外部卷-序号` | `外部卷-1` |

完整规则见 `references/开源与可移植性.md`。

## 验收清单（每次交付前自查）

**出卷时：**

- [ ] **大纲是否经用户确认过**才出卷？（不许跳过确认直接出）
- [ ] **每道题是否都带证据等级**（A/B/C/D）？D 级是否写了「建议考前确认」？
- [ ] **有没有伪造引用**（没原文却写「课本原文」）？
- [ ] **题量声明是否与大纲一致**？（第 2 步锁死，第 5 步照抄）
- [ ] **选项是否逐行排版**？（挤在一行 = 不合格，选项一长就没法读）
- [ ] **注意事项是否写成了考场须知**？（不许出现"填入括号内""2B 铅笔填涂""多选少选均不得分"这类）
- [ ] **加权是否只做加法**、总额不超过基础题量的 20%、且**跳过了本轮已换皮的**？
- [ ] **加权说明那一行有没有输出**？

**刷题时：**

- [ ] **有没有多说话**（鼓励、总结、进度、引导语）？
- [ ] **判断题的各种写法都认吗**？（`对/错`、`√/×`、`T/F`、`1/0`——不许反问"这是什么意思"）
- [ ] **换皮是否在错题循环跑完之后**才开始？（循环中途不许做别的）
- [ ] **换皮是否保住了知识点**？（换了题面却换了知识点 = 不合格）
- [ ] **同一个知识点有没有被练两遍**？（加权与换皮的分工）

**通用：**

- [ ] **该落盘的是否真的落盘了**？写失败时是否如实说了？

## 成本参考

按当前主流 API 价格量级，一次性的资料塌缩 + 出卷，单门课通常落在 **1-3 元**区间；六门课合计通常不到 20 元。

**成本不是这个项目的约束。** 真正的约束是**资料完整度**和**答案可信度**。遇到「要不要为了省钱而省掉自筛」这类取舍，答案永远是：不要省钱，自筛必须跑。

## 这个工具的定位（写给 AI 的上下文，不必向用户复述）

用户对这个项目的定义是**心理工具优先，学习工具其次**。他要的不是「成绩无敌好」，是「**给你一个可以不害怕考试的力量**」——哪怕这一科没考好，还能觉得下一科可以考好。

三个推论，会影响你的取舍：

1. **可预期性比命中率重要。** 一份「我们知道它只能考这些」的卷子，比一份「押中率很高但你不知道它靠不靠得住」的卷子更有价值。
2. **不要制造新焦虑。** 不写「必考」，不报进度，不催用户刷完。**这个工具必须允许用户不完美地结束**——一份没刷完的卷子不该变成新的失败证据。
3. **但也不能自我麻醉。** 用户自己看清了这个陷阱：刷出来的「熟悉感」和真正的「会了」在体感上很难区分。所以证据等级制度不能省——他需要知道哪些答案是能信的。
